# PigComic — Design Decisions Log

Every choice below was made by the planner where the requirements were silent, following Trados/memoQ conventions and conservative defaults. Numbers are cited from `docs/SPEC.md`. Overturning one = edit SPEC + append a dated note here.

| # | Decision | Rationale |
|---|---|---|
| D-01 | External tools are **ported/reimplemented behind Core interfaces**, not shelled out to: LanMangaCount, TiaomanOCR, and PSDManga2XLSX are all WinForms drag-and-drop apps with no CLI, no args, and no library seam (verified by code inspection). | Shelling out is impossible; the count algorithm is ~15 lines and the XLSX layout is small; PigTranslate (a real class library) remains the only referenced external code. |
| D-02 | `content.xml` uses **no XML namespace**. | Simpler for implementers and for hand inspection; forward compatibility comes from unknown-node preservation, not namespaces. |
| D-03 | CAT-created bubble ids = `u` + 8 random lowercase hex, collision-checked. Generator ids stay deterministic (`b0001`, `b0002`, ... sequential across the chapter since D-49). | CAT must never renumber; random ids can't collide with the generator's deterministic scheme. |
| D-04 | LLM comments live in a dedicated `<llmComment>` element, separate from user `<notes>`; a new LLM run overwrites the old comment. | Keeps machine output from polluting user notes; overwrite avoids unbounded accumulation. |
| D-05 | Atomic save keeps **one** backup generation as `<file>.pcml.bak` via `File.Replace`. | Cheap extra safety on top of the journal; more generations = disk bloat for 100 MB packages. |
| D-06 | The loaded `XDocument` is the persistence model; domain objects are XElement-backed write-through wrappers (SPEC §5.8). | Only design that makes unknown-element/attribute preservation trivially correct with ordering intact; memory cost is negligible next to images. |
| D-07 | `project.json` is read/written via `JsonNode` (not typed POCO serialization). | Same forward-compat requirement as the XML: unknown properties must survive round-trip. |
| D-08 | "Delete project folder" is a **permanent** delete with a double-confirm checkbox (no recycle bin). | Recycle-bin APIs are Windows-only (breaks the cross-platform rule); double-confirm covers the risk. `.pcml` files live outside the folder and are never touched. |
| D-09 | TM stores **one target per (normalized source, speaker)**, newest confirm wins (upsert). Same source with a different speaker is a separate entry. **Owner-confirmed 2026-08-22**: per-speaker entries are a core requirement in the comic context; no multiple-variants mode. | Trados "overwrite existing" convention; the speaker dimension covers identical lines needing per-speaker translations. |
| D-10 | Quote unification maps `『』“”‘’` → `「」`; straight `"` and `'` are left untouched. | Straight quotes are direction-ambiguous; a wrong open/close guess would create false exact matches. |
| D-11 | No TM editor UI in v1; only "delete entry" from the results-box context menu. | Keeps scope down; bad entries are fixed by re-confirming (upsert) or deleting. |
| D-12 | Inserting a TM match replaces the **whole target** and collapses splits to 1 part (its marker resets to the source marker). Status → Draft, never auto-confirmed. | The TM unit is the whole bubble; per-part insertion of a whole-bubble target is undefined. Draft preserves "never auto-fill/confirm" spirit. |
| D-13 | When several earlier same-source bubbles qualify for the repetition offer, the **nearest preceding** one is offered. | Most likely to share local context; deterministic. |
| D-14 | The counter port reproduces LanMangaCount's algorithm exactly, **including its quirks**: only U+0020 stripped (`\n`, `\t`, U+3000 count toward MSWord), en/em dashes subtracted from MSWord only, ASCII runs collapse to `一` (thus +1 MemoQ each), UTF-32 code points for MemoQ vs UTF-16 units for MSWord. Not ported: the XLSX reading layer (`中文`-column detection, non-string-cell skipping) — PigComic counts model text directly. | Billing numbers must match the business-proven tool bit-for-bit on the same text; the XLSX layer is irrelevant when counting in-model. |
| D-15 | On-confirm QA errors are shown as markers but **do not block** confirmation. | memoQ-style; comic QA rules (line length) are advisory during drafting; F8 gives the blocking-style review pass. |
| D-16 | Unlocking a bubble restores `Translated` if the target is non-empty, else `Untranslated`. | Locked doesn't record its prior status; this reconstruction is right in practice. |
| D-17 | New bubble `Order` = after the last bubble whose marker Y is above the new one; subsequent orders renumber. `Order` values are mutable; only ids are immutable. **Amended 2026-08-25 (D-49)**: `Order` is now chapter-global rather than per-page. | Y is the best automatic guess for reading order on a strip; the requirement "never renumber" is about ids. |
| D-18 | Default split-part placement. **Superseded 2026-08-25 by D-50**: with markers instead of regions there are no bands to cut, so part 1 sits at the source marker and each later part is offset 48 px further down in strip coordinates. | Keeps the crosses from stacking on top of each other while staying trivially predictable; the user drags them anyway. |
| D-19 | Find/replace hits demote `Translated`/`Reviewed` bubbles to `Draft`; `Locked` bubbles are skipped. | Trados marks edited segments unconfirmed; replaced text was never human-confirmed in its new form. |
| D-20 | Chapter XLSX export is a **native Core reimplementation** of the proven layout (`原件/<source label per D-33>/译文/审校/特殊要求备注`, 425 px thumbnails, row-height-walk placement) rather than calling PSDManga2XLSX/TiaomanOCR. | See D-01; also those tools depend on Photoshop/Azure respectively, which the CAT must not. |
| D-21 | Optional very-hidden `_pigcomic` data sheet in exports, **default off**. | Full-fidelity round-trip data is useful internally but could leak speaker names/notes in client deliverables. |
| D-22 | TBX forbidden terms map to `administrativeStatus = deprecatedTerm-admn-sts`. | The standard TBX-Basic value closest in meaning; round-trips through mainstream tools. |
| D-23 | Undoing a confirm reverts status/text but **leaves the TM entry**. | Trados/memoQ behave this way; deleting TM entries on undo would require TM versioning for marginal benefit. |
| D-24 | Placing and dragging a marker is the one mouse-required feature; everything else is keyboard-operable. **Amended 2026-08-25 (D-50)**: this is now a single click rather than dragging out a rectangle, so the mouse-only surface shrank further. | Picking a point on artwork by keyboard is high-cost, low-value; the translate loop itself stays 100% keyboard. |
| D-25 | Media zip entries stored with `NoCompression`; every save rewrites the whole archive on a background thread. | JPEG/PNG don't compress further; uncompressed storage makes the rewrite a fast stream copy (~1 s for 100 MB on SSD). The journal covers the between-saves window. |
| D-26 | Match scores: exact = 100, context boosts (+1 same character, +1 same kind, +1 previous-bubble match) displayed above 100 up to **103%**. Fuzzy floor 70%, candidates Dice ≥ 0.4 cap 50, results cap 20. | memoQ's 101/102% convention extended to the three specified boosts; caps per requirements. |
| D-27 | TM/TB query debounce 150 ms; autosave default 180 s; tile size 512 px; tile cache budget 384 MB; undo depth 200. | Conventional values; all but tile size are configurable or trivially changed constants. |
| D-28 | Project language pair is fixed at creation; a `.pcml` with a different pair refuses to open into the project. | One TM/TB per project makes mixed pairs meaningless and dangerous. |
| D-29 | Enter on an **empty** target moves to the next bubble without changing status or writing TM. | Prevents accidental "Translated with empty target" states; matches Trados behavior of not confirming empties silently. |
| D-30 | TMX/TBX import/export implemented natively in Core behind `ITmExchange`/`ITbExchange`; PigTranslate is NOT used for them (it has readers only, no TMX/TBX writers — verified). The interfaces exist so the owner can re-route later. | Requirement asked for both directions; native implementation is the only complete option. |
| D-31 | LLM QA response contract = strict JSON array `[{id, comment}]`; malformed reply → error, nothing written. | Weak-model-proof parsing; partial garbage must not corrupt packages. |
| D-32 | The IME-safe Enter guard (no confirm while composition active) is built and validated in the M2 gate and reused verbatim by the M5 editor. **Amended 2026-08-23**: `PartTextEditor` also keeps `TextAlignment.Left` + top/left content alignment while editing — see D-39. | The single most likely CJK-input bug class; gating it early is the point of the spike. |
| D-33 | **Owner directive 2026-08-22**: chapter-export source column header follows the actual source language — `zh`→`中文`, `ja`→`日文`, `ko`→`韩文`, `en`→`英文`, else the BCP-47 tag. Labels chosen by planner in simplified Chinese to match the legacy sheet's other headers (`译文/审校`). | Language pair is always known in PigComic; counting is built in, so LanMangaCount's `中文`-header detection no longer constrains the deliverable. |
| D-34 | **Owner directive 2026-08-22**: journal granularity is **confirm-only** — one flushed full-bubble snapshot per confirm, no other journal I/O. Crash loss is bounded to unconfirmed work since the last save/autosave. Snapshot-upsert replay (recreate missing bubbles) is the planner's design detail. | Keep the program light with minimal input-path latency; confirmed segments are the only thing that must never be lost (matches the original requirement's wording "each confirmed edit"). |
| D-35 | **Owner directive 2026-08-22**: LLM QA prompt is a per-project editable file; a per-project **memory file** (`llm-qa-memory.md`) is sent with every run and may be fully replaced by the model's response; provider and model are user-selectable per project, defaulting to `claude` / `claude-opus-5`. Planner details: JSON-object response contract `{comments, memory}`, 16,000-char memory cap with reject-on-overflow, settings dialog with prompt/memory/provider tabs. | Persistent reviewer memory gives run-to-run consistency (voice notes, terminology); full-replace semantics are the simplest contract a model can follow reliably. |
| D-36 | **Owner directive 2026-08-22**: the translation view is plain LTR top-to-bottom; all automatic ordering/placement logic uses the marker's **Y only**. X is recorded, drawn, and editable (needed for PSD export) but never drives CAT behavior. RTL + vertical typesetting concerns exist only in the deferred PSD export. | Keeps the editor simple; typesetting direction is a rendering concern of the final deliverable, not of translation. |
| D-38 | **Spike finding 2026-08-22 (M3.4)**: the §7.7 table requires fuzzy matches whose gram Dice is below §7.5's 0.4 threshold (rows 2/18 `안녕하세요` vs `안녕 하세요`, row 9 `你好吗?` vs `你好嗎？` — zero/shared-one gram overlap), while rows 12/16 must stay "no match". Resolution: retrieval candidates = exact ∪ gram-Dice ≥ 0.4 ∪ **substring share** (any ≥2-rune query gram contained in the entry's `source_norm`, or vice versa); over-retrieval is always pruned by the base-70 floor, which is exactly what keeps rows 12/16 no-match. Gram extraction for token-class langs additionally indexes the whole normalized string (removes the ko/full-string hole). | The normative table is the contract; the mechanics are extended minimally to satisfy every row of §7.7. Revisit if the owner re-specifies retrieval. |
| D-37 | **Spike finding 2026-08-22 (M2.3)**: SkiaSharp 3.116 bundled codecs return `Unimplemented` for JPEG `SKCodecOptions.Subset` region decode AND for PNG `StartScanlineDecode`/scanline-band reads on Windows. Per SPEC §20's sanction, the tile decoder falls back to **one full decode → immediate slicing into tiles → kept in memory per open page**, applied only because the 1000×40000 strip's full RGBA size is 160 MB ≤ the 256 MB rule; the guard refuses larger images with a clear error. Re-verify region/scanline decode on future SkiaSharp upgrades; the fallback stays until then. | The spec explicitly blesses this fallback; correctness > micro-optimization for the spike. |
| D-39 | **Owner-reported defect 2026-08-23 (SPEC §21)**: JA IME showed neither the current caret nor the henkan-ing word, and ZH IME showed no caret while editing Pinyin. First hypothesis — that `PartTextEditor` centering text desynced the composition caret — was **superseded** by D-40 after the owner confirmed the defect also reproduces in a plain (left-aligned) TextBox (the New Project title field). Left/top alignment is still retained (harmless, keeps caret in-flow), but it was not the root cause. | Initial analysis was incomplete; corrected by D-40. |
| D-40 | **Owner-reported defect 2026-08-23 (SPEC §21 escalation — custom IME client)**: the real root cause is that Avalonia 11.x's Win32 **IMM32** path (`Imm32InputMethod.HandleComposition`) reads only `GCS_COMPSTR` and calls `Client.SetPreeditText(composition)` with **no caret position and no conversion-clause data** — it never forwards `GCS_CURSORPOS`, `GCS_COMPCLAUSE`, or `GCS_COMPATTR`. (Confirmed in 11.2.5 AND 11.3.20. **Upstream status re-verified 2026-08-23 — see `docs/IME_HANDOFF.md` §3.1; the earlier "unreleased master" claim here was partly wrong**: the caret fix PR #21632 merged 2026-06-24 and **shipped in 12.1.0/12.1.1**, but was never backported to 11.x; clause highlighting is **not fixed in any branch or release** — #21647 is an open issue and #21648 an unmerged prototype PR. Note `SetPreeditText(string, int?)` already exists in 11.2.5; only the Win32 wiring was absent.) Result: the in-composition caret defaults to end-of-string (ZH Pinyin caret lost) and no active-segment highlight is possible (JA henkan word not shown). KO 2-beolsik masks it because jamo composes one glyph at the caret with the cursor always at the end. **Fix**: a custom `TextInputMethodClient` (`ImeTextBoxInputMethodClient`) that on `SetPreeditText` queries the focused HWND's IMM context directly for caret + clause data, feeding a clause-aware `ImeTextPresenter` (active henkan clause reverse-video via `ActiveClause`, others underlined; caret from GCS_CURSORPOS). The committed document text is NEVER mutated by composition. `PartTextEditor` installs the client on the Tunnel route with handledEventsToo (so the base TextBox bubble class-handler is skipped) and uses the `PartTextEditorTheme` (PART_TextPresenter = ImeTextPresenter). | Correct clause-aware IME rendering is impossible with Avalonia's stock IMM32 forwarding; the escalation is mandated by SPEC §21. KO/other no-clause IMEs degrade to the base flat-underline rendering. |
| D-41 | **Owner directive 2026-08-23 — upgrade to Avalonia 12.1.1** (resolves the former OPEN_QUESTIONS Q6; the app is unfinished so an overhaul was acceptable). Rationale: the in-composition caret fix (upstream PR #21632) ships only on the 12.x line and was never backported to 11.x, and clause highlighting is unavailable everywhere, so staying on 11.2.5 meant carrying a hand-rolled fix for a problem upstream had already solved. **Consequences applied:** (a) SkiaSharp pinned to 3.119.4 to match; (b) the legacy `OpenFileDialog`/`SaveFileDialog`/`OpenFolderDialog`/`FileDialogFilter` types are gone in 12 → all 8 call sites moved behind a new `Services/FilePickers` wrapper over `IStorageProvider`, which also removed a UI-thread-blocking `.GetAwaiter().GetResult()` in RelinkDialog; (c) compiled bindings are default-on → `DataTemplate`s need `x:DataType`; (d) `OnGotFocus`/`OnLostFocus` now take `FocusChangedEventArgs`; (e) RadioButton `Checked` → `IsCheckedChanged`; (f) `GenericTextRunProperties` and `TextLayout` ctors reordered (`fontFeatures` moved last); (g) the custom IME client now takes the caret from Avalonia's `SetPreeditText(text, cursorPos)` and reads **only** clause data from IMM32 — which deletes the old caret-stuck-at-0 bug by construction rather than fixing it. | Upstream parity for the half upstream solved; PigComic keeps a custom client only for the half (henkan clause highlighting) that no Avalonia release provides. |
| D-42 | **`--smoke` self-check added 2026-08-23** (`src/PigComic.App/SmokeTest.cs`, run as `PigComic.App.exe --smoke`): verifies the PartTextEditorTheme resolves and applies, that `PART_TextPresenter` is an `ImeTextPresenter`, that a clause-highlighted preedit lays out, and that every window's XAML constructs. Required in the verify loop alongside build/test. | The Avalonia upgrade's most dangerous failure mode is XAML that still *compiles* but no longer *applies* (a renamed Fluent key would silently disable the IME highlight). Neither `dotnet build` nor `dotnet test` can catch that, and Avalonia controls cannot be instantiated under the xunit runner without deadlocking (IME_HANDOFF §8), so it is a separate executable mode. |
| D-43 | **Owner directive 2026-08-23 — modern-flavor IME composition rendering** (Win11 Notepad/Excel style: colored composition text + colored background on the active henkan clause), replacing the reverse-video/underline look; PigComic aims to be the first CAT tool with it. Strategy per `docs/IME_MODERN_COMPOSITION.md` (investigation verified against Chromium/Firefox/Windows-Terminal/WPF sources and Avalonia 12.1.1): **Phase A** — capture IMM32 clause data *in-message* via a `Win32Properties.AddWndProcHookCallback` snapshot (root cause of the ATOK no-clause defect: reading GCS_COMPCLAUSE/COMPATTR after Avalonia's own ImmGetContext/ImmReleaseContext cycle is off-contract — "the IMM removes the information when the application calls ImmReleaseContext"; CUAS demonstrably supplies clause data for ATOK, per Chromium's decade on that path). **Phase B** — segment-model renderer in the modern palette. **Phase C (M-TSF track)** — a per-control `ITextStoreACP` text store rendering TIP-specified `TF_DISPLAYATTRIBUTE` colors verbatim (ATOK user palette, exact Notepad parity; Windows Terminal is the rendering template; CsWin32 interop verified building locally). | The classic flavor in VSCode/WPF is a rendering *choice*, not a data limitation; faithful display-attribute rendering is both the modern UX and the only way to honor per-IME user color settings. |
| D-44 | IME segment/decoration types mirror upstream Avalonia PR #20890's shapes (`ImeSegmentKind` = `Input/Converted/ConvertedTarget/TargetNotConverted/InputError` ≙ `TextInputDecorationKind`; optional explicit Foreground/Background/Underline like `TextInputDecoration`), and the private TSF store is gated by an app setting plus an Avalonia version check so it stands down when `Win32PlatformOptions.UseTsfTextInput` ships upstream. | Upstream is heading the same way (WIP, no timeline); shape-compatibility makes eventual migration a deletion, not a rewrite. |
| D-45 | **D-43 Phases A+B implemented 2026-08-24** (PLAN M2.6/M2.7). Structural rules established, and deliberately load-bearing: (a) `imm32.dll` is imported in **exactly one file**, `Ime/ImeMessageMonitor`, which only runs on the WM_IME_COMPOSITION message stack — making the off-contract late read that broke ATOK impossible to reintroduce by accident; (b) the hook is an observer that never sets `handled`, so Avalonia's own IME handling is untouched; (c) the caret continues to come solely from Avalonia's `SetPreeditText` cursorPos, and the no-clause degrade path (single `Input` segment) is smoke-asserted to preserve it — that is the Chinese-caret regression guard; (d) segment kinds are named for upstream's `TextInputDecorationKind` (D-44). A `CaptureEnabled` kill switch (`PIGCOMIC_IME_NO_HOOK=1`, plus a checkbox in the gate window) allows an instant A/B, because "does reading IMM32 early disturb the composition?" is the one question that cannot be answered without a real IME session. | Keeping the fragile interop in one message-scoped place is what makes the fix durable; the kill switch converts the single unverifiable risk into a one-click diagnosis for the owner rather than a support mystery. |
| D-46 | **Multi-line composition defect fixed 2026-08-24** (owner-reported: last line rendered blank, its text vanished while typing, caret stranded on the previous line, candidate window frozen; single-line unaffected, zh-CN mostly unaffected). Two independent causes, both in our clones of Avalonia internals. (a) `ImeTextPresenter.CreateLayoutInternal` passed `Bounds.Height` as the layout's `maxHeight`; `TextLayout` silently **drops lines that do not fit**, so a 4-line composition laid out as 3 and discarded 13 characters — the blank line, the stranded caret and the mis-placed candidate window all follow from that one value. The base `TextPresenter` measures with `(width, PositiveInfinity)`, confirmed by reading its private `_constraint` ("382, Infinity" where `Bounds.Size` was "382, 68"); height is now never constrained. Single-line escaped it because one line always fits, and zh-CN mostly escaped it because narrow ASCII pinyin does not push the last line past the bottom the way wide kana/hangul do. (b) `ImeTextBoxInputMethodClient` never raised `CursorRectangleChanged` after installation, so Avalonia placed the candidate window once and never re-queried it; it now subscribes to `TextPresenter.CaretBoundsChanged` (public) and reports the rectangle at `CaretIndex + PreeditTextCursorPosition` rather than at the preedit start. Guarded by a `--smoke` check that reproduces the exact case and was verified to fail before the fix. | The bug class is "faithful-looking clone of a private framework method that differs in one argument"; it is invisible to the compiler and to unit tests, so the regression guard matters as much as the fix. Confirmed separately that `TextViewVisual` = presenter while Avalonia's own client still transforms the rect to the TextBox, so our transform was correct and was left alone. |

| D-47 | **Owner-reported crash 2026-08-24 (first editor session) — dispose-then-read on Avalonia Bitmap.** `TiledImageControl.Install` disposed the replaced tile `WriteableBitmap` and then read its `PixelSize` for the byte-budget bookkeeping; any access on a disposed Avalonia `Bitmap` throws `ObjectDisposedException` (fatal via the UI-thread exception). Latent since M2.4, first reachable through the editor because a tile key being installed twice is a normal editor decode flow (TileReady raced Render's re-submit of a still-resident key). Fix: measure the old bitmap's dimensions **before** disposing it; also guard `OnTileReady` with a `_disposed` flag so posted tile callbacks landing after the window closes are dropped. Regression guard: smoke check "EditorView renders a real chapter and closes cleanly". | A disposable Avalonia `Bitmap` must be read before dispose, never after; the check belongs in the same lock section that removes it from the cache. |
| D-48 | **Owner-reported crash 2026-08-25 (clicking the p0002 bubble = page switch) — native UAF in `TileDecoder`.** `AccessViolationException` in `SKCanvas.DrawBitmap` on a worker thread: `RegionImage` returned the shared `_full` SKBitmap from `FullImage` under `_sync`, then called `DrawBitmap(src, …)` **outside** the lock, while the UI thread's `SetImage` → `TileDecoder.Dispose` (page switch) freed `_full`'s native memory mid-draw. Fix: the whole crop (including the `DrawBitmap` read) now happens inside `_sync`, and a `_disposed` flag makes `DecodeTile`/`EnsureCodec` throw `ObjectDisposedException` (worker catches → `TileFailed`, no crash) once a decoder is retired. `SetImage` may still block the UI thread up to one full-decode (~1 s) waiting for the lock — accepted; correctness over page-switch smoothness until M11. | Skia native objects shared across threads must never be read outside the lock that guards their lifetime; the "snapshot then draw" pattern is a use-after-free. |
| D-52 | **Owner directive 2026-08-25 — confirm-loop shortcuts flipped.** In target part editors, plain `Enter` now inserts a line break and `Ctrl+Enter` is the confirm gesture (previously Enter = confirm, Shift+Enter = newline, Ctrl+Enter = confirm-and-skip-confirmed). `Ctrl+Shift+Enter` (Reviewed) is unchanged. Rationale: multi-line comic targets are typed with Enter, and confirming with a stray Enter was a one-way door (status + TM upsert); modifiers make the expensive action deliberate. **Part-walk**: a confirm gesture on a non-last part moves focus to the next part editor within the same bubble — no status change, no TM write; only confirming the LAST part commits the bubble and advances to the next. (`PartViewModel.Index` is 1-based, so "last" = `Index == Parts.Count`.) So Ctrl+Enter is "next field, committing when you run out of fields" — Tab also moves between parts but never commits. **Mechanics**: `PartTextEditor.EnterInsertsNewline` (default false — the F2 source editor and dialogs keep Enter-to-commit/ConfirmOnEnter untouched; both modes share the IME-safe guard). **"Next available segment"**: advance-after-confirm now skips `Locked` bubbles always, and skips `Translated`/`Reviewed` when the new **"Skip confirmed"** option is on (default on). The option is a status-bar checkbox for easy access (`EditorViewModel.SkipConfirmed` ↔ `ConfirmService.SkipConfirmed`), persisted in `registry.json` under `editorLayout.skipConfirmed` (same merge-preserving `EditorLayoutStore`); it moves into the settings window with M8.6. `KeyBindings.IsConfirmNextUnconfirmed` renamed `IsConfirm`. **Focus bug found 2026-08-25 while testing this**: `FocusFirstPartOfSelected`/`FirstEditorOfSelected` did `GetVisualDescendants().OfType<PartTextEditor>().FirstOrDefault()` — which returned the row's collapsed inline `SourceEditor` (declared first in the template), not the target part editor, so after a confirm the caret stayed in the old bubble and the new textbox never activated. Latent since M5.4 (the smoke checked status, not focus). Fixed by filtering `Name != "SourceEditor"` and matching `PartViewModel.Index` precisely; `_lastFocusedEditor` is set synchronously in a `FocusEditor` helper (Focus/GotFlow is async in the headless host). Smoke +3 checks (key routing both modes + a part-walk check on the example chapter's 2-part b0002) + a VM↔service plumbing assertion in the editor check. | Comic targets are multi-line prose, not single segments; Trados-style Enter-to-confirm punishes the common case (typing a newline) and punishes a stray Enter with an irreversible status+TM write. The part-walk lets a translator step through a split bubble one Ctrl+Enter at a time and commit only when the whole target is done. The skip option is a stable preference, not a per-session toggle, hence persistence now and a real settings home later. |
| D-53 | **Owner-reported "TM isn't working" 2026-08-25 — silent store-open failure.** After the D-51 default language-pair flip (ja→zh-Hant became zh-CN→ja), the debug `strips/tm.db` still held the old pair; `TmStore`/`TbStore` throw `InvalidOperationException` on a language-pair mismatch (D-28), and `EditorView.OpenStores` caught it, set `_tm`/`_tb` to null, and wrote only to `Debug.WriteLine`. `MatchListViewModel` then had a null `_service` and its `DebouncedQuery` set `StatusText = ""` and cleared rows — indistinguishable from a legitimate "no matches". So TM appeared broken with **zero feedback**. (The write/read engine itself was untouched by the overhaul — confirmed by a fresh matching store landing a 102% context-boosted exact match in the new smoke check.) **Fix**: `OpenStores` captures the exception message into `_storeError`; `MatchListViewModel.StoreError` surfaces it in the results-box status as "TM/TB unavailable — <reason>" (and a distinct "not opened (open via a project folder)" message when no project folder was supplied). The smoke editor check now passes `tmp` as the project folder (it never did — TM was never wired in smoke) and asserts a confirm lands a ≥100% TM match on re-select; this was the M5.4 acceptance gap that hid the regression. | A silent degrade to "empty results" is the worst failure mode for a feature whose absence looks identical to its presence; the mismatch is a real, expected condition (language pair changes during development, a user re-targets a project) and must be explained, not hidden. The smoke gap (no project folder → no store → no TM path exercised) is the deeper lesson: an acceptance written as "TM rows appear" was never actually run headless. |
| D-54 | **M6 marker-interaction details settled 2026-08-25.** (a) Hit-test tie rule: a split bubble's **part 1 marker coincides with the source marker by default** (D-18), so the source cross and part 1's cross occupy the same strip point; the hit-test gives the **source marker precedence on ties** (source is checked first with a strictly-less comparison) — dragging near the main cross moves the source, never part 1. (b) Drag commits on mouse-up as one Core mutation via `SetMarker`/`SetPartMarker` (undoable when M9 lands); a press+release without movement skips the commit entirely (no spurious dirty). (c) During the drag the model is untouched — the control renders a local preview cross; Esc cancels without a write. (d) Placement click stays armed on Shift (SPEC §15.2); Ctrl+B toggles; Esc disarms. (e) **Wiring fix**: the inner parts `ItemsControl` realizes fresh part editors after an Alt+1/2/3 split that the outer `ContainerPrepared` never re-fires — the first version silently left the new editors unwired (Ctrl+Enter/Tab dead); `SegmentListView.WireEditorsIn` now subscribes to each row's `Parts.CollectionChanged` and re-wires on change. (f) The spec's boundary beep for Tab-at-the-end (SPEC §14.3) is omitted — `System.Media.SystemSounds` needs the Windows-only `System.Windows.Extensions`; the move simply does not happen (noted in the plan). | Points, not boxes, keep dragging trivial; the coincident part-1 marker is the one genuinely ambiguous hit-test case and "source wins" is the only rule a user can internalize.
